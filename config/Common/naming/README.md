# naming/ — 命名詞彙字典（維護指南與 template）

這個資料夾是**命名卡控的權威來源**：規範哪些縮寫不能用、同義詞以哪個為正規、
（選用）認可用詞白名單。維護好這份字典，三個地方同時生效：

1. **治理（govern mode）**：`naming_glossary` 閘門規則逐欄檢查
   （`no_banned_term`／`no_alias_term`）
2. **設計（design mode）**：整份字典餵進設計 prompt，agent 起草命名時直接遵守
3. **設計預檢**：草稿 DDL 用同一套規則試跑，縮寫在設計階段就被擋下

---

## 檔案規則

- 本資料夾內**任意檔名的 `.md` 都會被當成字典合併載入**（依檔名排序），
  只有 `README*` 會被跳過——可以拆多個檔（如 `glossary.md`＋`finance_terms.md`）
- **Common 恆載入**；`config/<域>/naming/` 的字典**疊加在 Common 之上**
  （同一個詞後載入者覆蓋，可做領域例外）
- 段落標題以**關鍵字**辨識（層級不限 #～######）：
  含「禁用／縮寫／banned」→ 禁用詞；含「別名／alias／同義」→ 別名；
  含「標準／standard／白名單」→ 標準詞。
  檔內有表格卻沒有可辨識標題會**直接報錯**（不會靜默失效）
- 格式驗證：`python config_check.py`（❌ 時依本 README 修正）

## 比對方式（避免誤解）

欄位名以 `_` 切成 token **逐一比對**：`cust_id` 會命中禁用詞 `cust`；
`custom_field` 不會（`custom` 不是 `cust`）。詞條請一律**小寫**。

## Template（新增檔案時複製這份骨架）

```markdown
# <主題> 詞彙字典

## 禁用詞
欄位名含左邊的詞（縮寫）就報違規，建議改用右邊的標準詞。

| 禁用 | 改用 |
|---|---|
| cust | customer |

## 別名
同義但非標準的完整詞 → 正規詞（全公司統一用右邊的詞）。

| 別名 | 正規詞 |
|---|---|
| client | customer |

## 標準詞
認可用詞白名單（清單項目，一行一詞）。**留空 = 不啟用白名單模式**，
只用上面兩個黑名單。

- customer
- amount
```

## 三節的維護語意（什麼情境加在哪一節）

| 情境 | 加在哪 | 效果 |
|---|---|---|
| 「不准用這個**縮寫**」（如 `tel`） | 禁用詞：`tel → phone` | 欄名含 `tel` 就報，並建議改用 `phone` |
| 「這幾個**同義詞**統一用某個」（如 mobile/cellphone → phone） | 別名：一詞一列，右邊都填 `phone` | 用到別名就報，指向正規詞 |
| 「**只有**這些詞可以用」（含認可縮寫如 `id`、`utc`） | 標準詞白名單 | 需最嚴管制時才啟用（見下） |

### 啟用白名單模式（進階，預設關閉）

1. 在「標準詞」節把**全部**認可用詞列完整（含認可縮寫）
2. 在 `config/Common/knowhow/gating/naming_glossary.md` 的卡控區加一行
   `require: term_in_glossary`

啟用後**不在白名單的詞一律報**——請先確認清單完整再開，否則會大量誤報。

## 生效與變更紀錄

- **編輯後下次 `python run.py` 立即生效**——字典是知識輸入，每輪重新載入，
  不需 compile、不會動 `rules_history`
- 想把命名檢查升級成**會擋**：改 `naming_glossary.md` 規則的
  `enforcement: warning` → `blocking`（規則變更會被 `rules_history` 記錄）
- 詞條的實質增刪屬**語意內容**：由維護者人工決定；agent 只能在使用者
  同意下代為修改
